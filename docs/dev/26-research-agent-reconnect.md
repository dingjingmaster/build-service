# 26 Agent 断线重连调研

- 日期：2026-10-21；级别：L3（连接生命周期、异步任务清理影响稳定性）。
- 用户现象：server 重启后 agent 必须手动重启；期望同一进程持续重试并自动恢复。
- 授权边界：只修改 agent 实现及其测试、相关文档，server 实现不动，不部署、不提交。
- 初始证据 E1：用户报告；静态确认接收无超时，writer 失败不传播，错误 `?` 绕过清理。尚不能断言真实环境的唯一根因。
- 复现策略：本地 TCP/WebSocket 对端不发送 HelloAccepted、不回应 Ping，以及多次主动断线；以真实 agent 路径验证。
- 已确认方案：标准 Ping/Pong 探活（5 秒间隔、15 秒回应期限），连接/Hello/发送超时 10 秒；已注册连接结束后立即重试，连接或注册失败后每 3 秒无限重试；统一清理并保持现有取消任务策略。
- 兼容性：现有 axum 自动回复 Pong；无新依赖、无 JSON 协议或 INI 变更。
- 审视：不扩展任务续跑；不操作真实服务。单连接错误清理必须覆盖正常退出、解析错误、发送失败和超时。

- 复现证据升级 E3：修复前三个自动化用例分别因无 Hello 超时、无 Pong 超时、未立即重连失败；修复后均通过。真实部署现象仍未现场复现。
